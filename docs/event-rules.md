# 今回のルールと採点への反映

対象日・更新日: 2026-10-18（Asia/Tokyo）。今回ユーザーが提供した[確定ルール本文](../reference/event-rules-2026-10-18.md)を優先します。[開催要項](https://luma.com/OpenAIDevDay2026CommunityHackathonTokyo)と[HawkieさんのQ&A記録](faq-notes.md)の2026-10-17取得分は、更新と矛盾しない部分の補足です。今回の更新で開催ページを再取得したわけではありません。

## 確定した4観点

| 公式の観点 | 公式本文の問い | 本ツールで確認する根拠（独自の指針） |
|---|---|---|
| 新機能の活用 | DevDay 2026で発表された機能を、目的に合った形で活用しているか？ | 発表機能と目的、実際の呼び出し、入力→処理→出力の対応 |
| 使いやすさ | 他の人にとって使いやすいものになっているか？ | 初めて使う人の操作、説明、入力例、エラー・待機時の挙動 |
| 有用性 | 他の人にとって今後どれだけ役に立つ可能性があるか？ | 誰のどの課題を解くか、利用前後の変化、今後の利用可能性 |
| 独創性 | 着眼点や解決方法にオリジナリティがあるか？ | 着眼点、解決方法の工夫、従来の方法との具体的な違い |

**4観点は公式、各0〜10点・等配点・合計40点は本ツール独自の仮定です。** 公式の配点・重み、詳細な採点指針、点数アンカーは本文にありません。共通アンカーと評価指針は比較のために設定しており、本番点数や通過確率の再現ではありません。

新機能の利用は`new_features`の点数へ直接反映します。`devdayUsage`はその根拠を詳しく整理する欄です。単なる機能名の記載、モックや未接続コード、実装予定を実利用と同等に扱いません。DevDay 2026の発表機能であると判断する根拠が入力にないときは未確認とし、モデルの推測で補いません。対象リポジトリの外部リンクは開きません。

以前の「技術的な実装・UX・インパクト・アイデア」の4項目は、前回の公開コードを分析した記録としてのみ残しています。技術的な完成度や設計は現在の4観点を支える根拠にし、独立項目や追加ボーナスにはしません。旧版と新版の点数は直接比較できません。同じ材料で比較したい場合は、旧runの`evidence.json`を新版で再採点します。

## 成果物・開発・事前準備

以下は今回提供された確定ルールに基づきます。

| 条件 | 本ツールの扱い |
|---|---|
| 成果物はWebで公開されているもの。ChatGPT Sites、Cloudflare Workers、Vercel等へデプロイ | URL・実装・デプロイ設定の記述を確認。設定だけで公開済みと認定せず、稼働確認は別途必要 |
| ハッカソン中の開発はCodex CLI / Codex App / ChatGPT Work | 利用申告を記録。開発手段全体を独立検証できないためunknown |
| Claude Codeは禁止。Cursor・Devin経由のOpenAIモデル利用も禁止 | 開発手段の条件に含める。モデルがOpenAIであっても許可にはならない |
| OpenAI OAuthを使うサードパーティハーネスは禁止 | 開発手段の条件に含める。提出作品のSignIn利用可否と区別する |
| 事前に成果物を作ってくるのは不可。未公開の新規プロトタイピングは可 | SNS等での公開歴、事前の完成度、当日の制作範囲は人が確認するためunknown |
| 他ハッカソンの提出作品のチューンナップ等は不可 | `no_prior_hackathon_submission`として独立確認。提出歴は自己申告だけでは検証できずunknown |
| DevDay発表関連情報の下調べは可・推奨 | 事前の調査を違反と扱わない |
| デプロイに不慣れな場合は事前準備を推奨 | デプロイ環境の準備と事前の完成品制作を区別する |

本ツールは事前の証拠収集・参考採点用で、作品の生成・修正ループは持ちません。これを根拠に、主催者が当日の利用を認めたとは判断しません。当日の開発には指定された3つのツールを使います。

`evidenced`は取得した根拠があるという意味で、全事実を独立検証したという意味ではありません。`needs_action`は対処が必要な材料がある状態、`unknown`は判断材料不足です。参加条件と作品点は別扱いとし、公式の失格判定はしません。

## 予選と本戦

- **予選はOpenAIのモデルによる自動評価。GPT-6.1 SolあるいはDecisions APIを予定。** どちらを採用するかは確定していません。本ツールはCodex CLI経由のGPT-6.1 Solを既定とし、Decisions APIの実行には対応していません。
- **本戦は主催者の判断か投票か未決定。** 本ツールでは本戦の結果を予測しません。
- 正確なモデル指定・effort、試行回数、集計方法、詳細な審査プロンプトは未確認です。

## 提出前に整えること

1. 提出する公開repoの1箇所に、必要なフロント/バックの実装を集める。
2. README冒頭で「誰の、どんな場面の、何が変わるか」を説明し、公開デモと操作手順を載せる。
3. DevDay 2026発表の機能名・発表情報の出典・採用理由・実装ファイル・実際の入出力を対応させる。
4. 使いやすさ、有用性、独創性を具体例とコードで説明する。予定・モック・実装済みを区別する。
5. 動画・画面・デモだけで伝わる部分は、テキストでも説明する。自己採点や審査AIへの命令は書かない。
6. `snapshot`で読まれる範囲を確認し、`judge`で根拠不足を見る。最新の観点は`rubric.json`、ルールは`event-rules.json`に保存される。
7. Web公開・ログイン・API制限は実機で確認する。制作ツール、未公開プロトタイプ、過去の提出歴はチームで事実確認する。

予選でデモURLを開かないという説明は、Web公開要件の免除を意味しません。
